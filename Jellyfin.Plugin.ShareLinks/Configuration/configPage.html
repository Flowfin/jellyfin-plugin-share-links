Share Links

The address this server is reached at from outside, with no trailing slash, for example https://media.example.org, or https://example.org/jellyfin when a proxy puts the server under a path. Every share link is built from it.
While it is empty, the link is built from what the incoming request said the server was. That is a header, which is text whoever made the request wrote, so a request carrying a forged host produces a link pointing at somewhere else, which you then send to a guest. Set this value and the request is not consulted at all. Behind a reverse proxy it is the only reliable answer, because the address the proxy passes on is not the one the guest typed.
A value that is not an absolute http or https address is refused when a link is built, and no link is produced. It does not fall back to the request, because a typo here would then quietly restore the behaviour this setting exists to remove.
How many shares may be live at once. Live means neither revoked nor past its expiry, so revoking a share or letting one expire frees a place.
How many live shares may name the same item. Several is the ordinary case of one title lent to several people; this is the bound that keeps a loop pointed at one item from consuming the whole server ceiling.
Checked when a share is created and never when one is resolved, so lowering it leaves links you have already handed out alone.
A fallback rather than a second ceiling. It has to be at least one day and no longer than the ceiling above, because a default longer than the ceiling is a configuration in which every share created without an expiry is refused.
Counted from the instant the share stopped answering rather than from when it was created. Zero deletes it at the first write after that instant, which is how you empty the store of what has expired.
Leave it empty for no ceiling. Zero is refused rather than read as no ceiling, because serve nothing and serve without a limit are opposite instructions. Megabits per second here; the record keeps bits per second, which is the unit the account switch takes.
A ceiling on the account rather than on the share, so a guest invited to two shares carries one allowance across both rather than one each.

A value this plugin cannot work under is refused as it is saved and the message names the setting. Editing the configuration file by hand passes through none of that, and there the refusal arrives later, when the setting is next read.

Shares

Every share the server holds, including the ones that have stopped working. A share that expired and a share that was never made look the same to somebody who is only told what is live, so the state column is what keeps them apart.

This page enforces nothing. Everything it offers is checked again on the server, and everything it hides is still reachable by anybody who can call the routes. The revoke button appears only on a share that is still live, because pressing it on one that has already stopped changes nothing; that is the server's rule and not this page's, and a second press is accepted and leaves the first press's instant, reason and revoker where they were.

Item Invited State Expires Ceiling Revoked

What is not here. There is no control that creates a share, because this plugin serves no route that creates one, and a link is therefore never shown on this page: only the keyed hash of a token is written down, so the server cannot produce a link a second time even when asked. The item is named by its identifier rather than by its title, because the listing answers with the identifier and nothing here asks the server for a title. The ceiling column is the share's own; which of the ceilings that apply actually wins is decided elsewhere and is not on this page.
